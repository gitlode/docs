# gitlode プロファイリングガイド

> PoC用の翻訳例です。人による翻訳レビューはまだ完了していません。

`--profile` を指定すると、ワーカーの実行に対してローカルのOpenTelemetry収集セッションが1つ有効になります。
プロファイリングしない場合と同じアプリケーションの実行経路、Git操作、プラグインのコールバック、JSONL出力を使用します。
レポートはSDKに依存せず、アプリケーションのリソースを破棄した後に作成されます。

## CLIの動作

最初にアプリケーションのサマリーを表示します。実行が成功し、quietモードでなければ、その後にProfileブロックを表示することがあります。
失敗した実行でもテレメトリーの終了処理は行いますが、プロファイルは表示しません。
`--quiet` は進捗、サマリー、プロファイルの出力を抑制します。
ローカルの初期化に問題が生じた場合、機密情報を除いた警告を出して抽出を継続し、Profileブロックは表示しません。

プロファイリングが無効な場合、ソース側のセッションはAPIのno-opテレメトリーを選びます。
このとき、ローカルSDK実装のインポート、SDKプロバイダーの構築、コンテキストマネージャーの登録は行いません。
有効化を要求した後に初期化が失敗した場合も、所有する部分的なリソースを片付けてからAPIのno-opテレメトリーへ戻ります。
ただし、この場合はSDKコードを既に読み込んでいる可能性があります。
[テレメトリーの契約](https://github.com/gitlode/gitlode/blob/90512564d76490088ecc99da7596128df1c45a2c/packages/gitlode/docs/design/telemetry.md#worker-telemetry-session)では、no-opのルートとコンテキストの意味を定義しています。
リリース時の検証では、出力されたバンドルとインストール済みCLI／ワーカーの実行について、この境界を確認します。
これらの機能検証は、実行時間のオーバーヘッドを定量化するものではありません。

## 共通の階層構造

表示では、保持されたすべてのSpan、カウンター、ヒストグラムを、計装Scopeの名前と任意のバージョンでまとめます。
各Scope内では、観測名の全体を `/` 接頭辞付きの行として直接表示します。名前空間によるグループ化は標準では無効です。
レイアウトの実験用に、ソースコード上で名前空間によるグループ化を有効にできます。
詳しくは[CLIのスタイルガイド](design/cli.md)を参照してください。
種類ごとのセクションやバッジは設けません。種類が異なる観測や、同じ名前を持つ複数のメトリックポイントも、それぞれ独立した行として扱い、種類と型付き属性で順序付けます。

見出しの余白も含めた、プレーン出力の例です。

```text
 Profile
   Scope: gitlode.git
     /gitlode.git.commit.walk  : calls=1, total=6.9s, avg=6.9s, max=6.9s, errors=0
     /gitlode.git.object.cache.lookup  : 670objects
      /gitlode.git.adapter = isomorphic-git
      /gitlode.git.object.purpose = materialize
```

Scope、名前、種類、型付き属性を並べ替えのキーに使い、文字列はコード単位順で比較します。
ソースコード上で名前空間によるグループ化を有効にすると、短い名前の測定値を名前空間の行に表示する場合があります。
名前自身が名前空間でもある場合、その属性を子の観測より先に表示します。
ドットの形式が不正な名前や、区切り文字、真偽値、数値と混同され得る文字列は、引用符で囲んでエスケープします。
受け入れられた未知の名前やプラグインのScopeにも同じ規則を適用します。Pluginsやfallbackという別枠にはまとめません。

## 値と診断情報

Spanには、呼び出し回数、合計時間、平均時間、最長時間、エラー数、上限を設けた属性サマリーを表示します。
カウンターには、保持された型付き属性の組み合わせごとに1つの値を表示します。
ヒストグラムには、サンプル数、合計、平均、nullになり得る最小値と最大値を表示します。
保持されたバケットを展開したり、パーセンタイルを計算したりはしません。
明示的なゼロはそのまま保持します。取得できない項目は `—` と表示し、仮のゼロには置き換えません。

時間にはns、µs、ms、sを、サイズにはB、KiB、MiB、GiBを使います。
値は最大4桁の有効数字で表示し、丸めによって次の単位に達する場合は単位を繰り上げます。
必要に応じて指数表記を使い、ゼロでない値が単なるゼロとして表示されないようにします。
測定値の数値と単位は続けて表示します。例えば `6.9s`、`1KiB`、`670objects` です。
丸めるのは表示時だけで、レポート内の値は元の精度を保ちます。

収集やライフサイクルに問題がある場合、Profileタイトルの後に簡潔な通知を表示します。
構造化された詳細情報は、根拠のある最も狭い位置、すなわちレポート、Scope、観測、ポイント、属性のいずれかに表示します。
観測を特定できても有効な結果がない場合、その行は `unavailable` として残し、有効な兄弟要素は通常の行として表示します。
発生回数、判明している損失量、不明な損失量、省略した診断情報は区別します。

通常のレポート構築に失敗した場合、通常のProfile表示経路で、検証済みの測定結果が存在するかどうかを説明します。
信頼できるスナップショットがなければ、3種類の結果はいずれも利用不可となり、部分的な測定値を再構築しません。
それ以前に発生した問題の出所を特定できない場合は、その旨も別に表示します。

利用可能な数値やスカラー属性値には、追加の強調を付けず、ターミナル標準の前景色を使います。
この本文としての扱いは、進捗表示と完了時の値でも共通です。
色と強調は階層や通知を補うものであり、プレーンテキストでも意味を保持します。
見出しの背景には左右それぞれ1文字分の余白を含め、プレーン出力でも同じ空白を保持します。
表示を調整する開発者は、[`design/cli.md`](design/cli.md)のソースレベルのスタイルガイドに従い、自分のリポジトリで出力全体を確認できます。

ターミナルの整形は人による診断のためのものであり、機械可読な互換性の契約ではありません。
プロトコルを必要とする利用側は、CLIの空白や句読点を解析するのではなく、ワーカー境界の構造化された `ProfileReport` を使用してください。
