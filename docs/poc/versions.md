# stable／next統合とバージョン切り替え

状態：2026-11-17にローカル実装・自動検証済み。オーナーによる操作確認待ち。
判断者：プロジェクトオーナー。次の対応：両SSGの切り替えを確認し、残るPoC評価へ進む。
SSG選定まで比較の根拠として保持する。

## 今回できるようになったこと

1回のビルドで、両SSGのstable／nextと英語／日本語を含む完全な比較成果物を作成する。
各ページ上部の「バージョン」（英語ではVersion）から、同じ言語・同じ文書の別バージョンへ移動できる。
現在のバージョンは太字で示す。バージョン間では見出しが異なり得るため、節のフラグメントは引き継がない。

stableとnextは別々にビルドするため、切り替え時はページ全体を読み直す。
一方のバージョンのクライアント側データを他方で使わないための処理である。
日本語の未翻訳ページでも、日本語URLを保って別バージョンへ切り替える。

stableには翻訳をまだ登録していないため、6文書とも英語フォールバックになる。
nextの日本語Profiling Guideをstableに流用しない。実運用での翻訳スナップショット方針は未決定のまま。

## 確認方法

すでに統合版をビルド済み。別々のターミナルで次を起動する。

```sh
npm run preview:vitepress
npm run preview:starlight
```

- VitePress：`http://127.0.0.1:4173/docs/vitepress/next/ja/profiling/`
- Starlight：`http://127.0.0.1:4174/docs/starlight/next/ja/profiling/`

上部のstableを選び、同じProfiling Guideの日本語URLへ移動し、英語フォールバックが表示されることを確認する。
nextへ戻ると日本語訳になる。別の文書や英語表示でも同じ位置を保って切り替えられる。
終了時は各ターミナルでCtrl+Cを押す。既に起動中の旧プレビューは停止してから起動し直す。

再ビルドは`npm run previews:build`、有限HTTP確認は`npm run previews:verify`。
`npm run previews:build -- stable`または`-- next`は、単独バージョンの診断用として残している。
単独ビルドにはバージョン切り替えを表示しない。統合版へ戻すには引数なしで再ビルドする。

## 構築・保守の比較

| 観点             | VitePress                                                       | Starlight                                                    |
| ---------------- | --------------------------------------------------------------- | ------------------------------------------------------------ |
| 追加した表示処理 | 標準テーマを拡張し、doc-beforeスロットへVueコンポーネントを配置 | PageTitleをAstroコンポーネントで包み、標準タイトルの前に配置 |
| 切り替え先の算出 | 現在のページ情報から言語と文書を取得                            | リクエストURLから取得。未翻訳の英語エントリーIDは使わない    |
| 統合・検証       | 共通処理で成果物を組み立て、横断リンクを検証                    | 同左                                                         |

どちらも小さなテーマ拡張が必要になった。共通の組み立て処理が作業の中心であり、この工程だけで
大きな優劣は判断しない。表示・操作の最終判断はオーナーの確認後に記録する。
追加の依存パッケージはない。

## 検証結果

- stable単独の両SSGビルドを先に検証し、成功を確認。
- 51テスト、format・lint・型検査に合格。
- 全4ビルドの文書表示・言語チェックに合格。
- 56ページ（2候補×2バージョン×2言語×文書6件と入口1件）で現在バージョン、
  同じ言語・文書への切り替え先、ページ全体を読み直す属性を検証。
- 成果物全体で3,111件のローカルhref/src参照を検証。H1・リンク先・フラグメント検証も成功。
- stable／next両方の英日入口、翻訳・フォールバック対象、文書と404をHTTP検証。
- 出力は`.generated/previews/combined-xOWlxK/dist`。64 HTMLファイル、合計6,736,306バイト。
  これは両候補を含む比較成果物全体の単発観測値である。

取得済みの英語文書は1つのステージング記録を4ビルドで共有する。
生成されたソースや来歴情報は公開するdistの外に保持する。毎回新しい成果物を作り、前回の出力へ追記しない。
全検証に成功した場合のみプレビュー参照先を切り替える。`.nojekyll`、比較入口、404も含める。
CIの既存ビルドコマンドも統合版を検証するが、ホスト上でのCI実行とGitHub Pagesへのデプロイは未実施。

## 未検証・制限

- 今回のブラウザでのクリック操作・モバイル表示はオーナー確認待ち。
- 6文書が両バージョンに存在する前提。片方にしかない公開文書の切り替え方針は今後の課題。
- 検索は無効。CSS内URL・srcset・インポート画像の対応は従来どおり未完了。
- 未翻訳文書への対応比較はオーナー判断で完了。PoC対象外文書へのGitHubリンクは許容した制限として維持。
- ローカル翻訳・設定をビルド中に編集しないこと。入力スナップショットは記録するが、同時編集を固定する機能はない。
- 本番用のURL確定、依存関係への対応、本番成果物からの比較用コード除去、SSG選定と公開承認は別工程。
