# 標準ローカル検索の比較

状態：2026-11-17に検索を有効化し、生成インデックスへの問い合わせを実施。オーナーによる両プレビューのブラウザ確認済み。
判断者：プロジェクトオーナー。次の対応：再現性・CI確認と最終評価へ進む。
検索は低優先度の比較項目であり、日本語検索の制約だけでPoC完了を妨げない。
SSG選定まで根拠を保持し、採用後の運用契約は設計・開発資料へ移す。

## オーナーによる評価

2026-11-17、両プレビューの検索機能をブラウザで確認した結果、両者とも必要十分であり、
機能面ではVitePressのほうが高機能と評価された。ただし、今回の選定の決め手とはしない。

- 検索は今回の主要な選定要因ではない。
- 標準機能での比較であり、カスタマイズによって結果が変わる可能性がある。
  実際に変わるかどうかは未検証であり、改善を保証するものではない。

以下の自動照会で観測した日本語語句の差は、限定した検索例の結果として保持する。
利用者による機能全体の評価とは評価軸が異なり、これを検索機能全体の順位に置き換えない。
検索の必要十分性は確認済みとして、追加カスタマイズで差を詰める作業はこのPoCでは行わない。

## 有効にした機能

| 項目                 | VitePress                                  | Starlight                        |
| -------------------- | ------------------------------------------ | -------------------------------- |
| 標準検索             | MiniSearchによるローカル全文検索           | Pagefindによるローカル全文検索   |
| 設定変更             | `themeConfig.search.provider: 'local'`     | 無効にしていた`pagefind`を有効化 |
| バージョン範囲       | ビルドごとに独立し、stable／nextを混ぜない | 同左                             |
| 言語範囲             | 閲覧中の言語のインデックス                 | 同左                             |
| 日本語の未翻訳ページ | 日本語URLの英語本文を検索対象に含む        | 同左                             |
| 検索UIの日本語化     | 今回は標準の英語文言。翻訳設定を追加できる | 日本語UI文言を標準で提供         |

外部SaaS、APIキー、独自の日本語分かち書き、全バージョン横断検索は導入していない。
既存の標準検索の性質を比較するため、検索順位・あいまい検索の設定は変更していない。

## 確認方法

ビルド済みなので、従来の`npm run preview:vitepress`と`npm run preview:starlight`で起動する。
検索ボタンから、まずnextの日本語表示で次の語句を検索する。

- `プロファイリング`
- `ヒストグラム`
- `カウンター`
- `OpenTelemetry`
- `全体`

英語表示では`profiling`や`CLI`を試す。stableへ切り替えた場合も、そのバージョン内の結果となる。
stableには日本語訳がないため、日本語本文の語句が見つからないこと自体は検索の欠陥ではない。
未翻訳ページは日本語表示でも英語の語句で検索できる。終了時は各ターミナルでCtrl+Cを押す。

再実行手順：

```sh
npm run previews:build
npm run search:verify
npm run previews:verify
```

`search:verify`は生成済みのMiniSearch／Pagefindインデックスを実際の検索エンジンAPIで照会する。
Pagefindの言語判定に必要な最小限のdocument情報をNode上で与えるが、検索UIやDOM操作は再現しない。
結果は生成ディレクトリの`search.json`に保存する。一時HTTPサーバーを使い、成功・失敗時とも停止する。
この比較スクリプトは固定したSSGのインデックス形式に依存するため、依存更新時に見直す。

## 観測した結果

nextの日本語表示での結果：

| 語句             | VitePress                                                           | Starlight                       |
| ---------------- | ------------------------------------------------------------------- | ------------------------------- |
| プロファイリング | 日本語Profiling Guideが見つかる                                     | 同左                            |
| ヒストグラム     | 日本語Profiling Guideが見つかる                                     | 同左                            |
| カウンター       | 日本語Profiling Guideが見つかる                                     | 同左                            |
| OpenTelemetry    | 他の未翻訳文書は見つかるが、日本語Profiling Guideは結果に含まれない | 日本語Profiling Guideも見つかる |
| 全体             | 結果なし                                                            | 日本語Profiling Guideが見つかる |

日本語Profiling Guideには`ローカルのOpenTelemetry収集セッション`や`出力全体`のような記述がある。
標準設定のMiniSearchは空白・句読点を主な語の区切りとするため、日本語に埋め込まれた語や語の途中を
見つけにくい場合がある。今回の結果はその制約と整合する。一方で日本語が全く検索できないわけではない。

VitePressは節単位の結果を返し、Pagefindはページを返すAPIを使って比較した。
単純なヒット件数は優劣の指標にしない。日本語サンプルは1文書のみなので、日本語検索全般の品質や
ランキング精度を断定するものではない。検索結果には本文以外のタイトル・来歴なども影響し得る。

8語句×2候補×2バージョン×2言語の問い合わせを行う。全結果について同じ候補・バージョン・言語の
範囲に収まること、公開ページと該当フラグメントが存在することを検証する。
存在しない語`zzzznomatchgitlode`は結果なしを確認する。

## 構築コストと暫定評価

有効化は両候補とも小さな設定変更で済んだ。検索機能そのものに追加パッケージは不要だった。
再実行可能な比較スクリプトがMiniSearchを直接使うため、既存のVitePress依存と同じ7.2.0を
開発依存として明示した。新しい検索方式への差し替えではない。

検索有効化後の統合成果物は`.generated/previews/combined-tf2nRh/dist`。
64 HTMLファイル、合計9,227,663バイト。検索インデックス・ランタイムも含む全候補の合計であり、
ブラウザが一度に取得する転送量ではない。単発のビルド時間はstableがVitePress 4,877ms／Starlight 4,967ms、
nextがVitePress 4,895ms／Starlight 4,795msだった。僅差を性能順位とは扱わない。

現時点では、両者とも基本的なローカル検索を実現できる。今回の少数の日本語語句ではStarlightが
見つけやすい例があった。VitePressの改善には分かち書きなどの追加検討が考えられるが、
低コストの標準機能比較という今回の範囲では実装しない。

## 制約

- ブラウザで検索モーダルを開く、候補選択、キーボード操作、モバイル表示は今回の自動照会では検証していない。
- 未翻訳の英語本文が日本語へ自動翻訳されて検索されるわけではない。
- 外部リンク先の未公開文書はインデックスに入らない。
- 複数バージョン横断検索や大規模文書群での速度評価は行わない。
- Pagefindの生成物は版によってAPIが変わり得る。比較用の型定義は利用する範囲のみを明示したもので、
  ブラウザの実装全体に型保証を加えるものではない。
