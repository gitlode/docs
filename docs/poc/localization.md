# 日本語対応の比較結果

状態：2026-11-16に実装・検証済み。2026-11-17にオーナーがプレビューを確認。
判断者：プロジェクトオーナー。次の工程：注釈の改善と再確認、stable／next統合。
SSG選定まで判断材料として保持し、確定した契約は設計資料へ移す。

## 現時点の評価

オーナーの確認では、英語・日本語ともに利用者視点の主要な機能に大きな差はない。
ただし未翻訳注釈は、Starlightではスタイルにより本文と区別できる一方、VitePressでは
プレーンな段落のため見逃す可能性がある。単なる装飾の好みではなく、未翻訳であることを
利用者に伝える機能の差として評価する。

評価は二つに分ける。

1. **必要な体験を実現できているか**：本文と区別でき、読み始める前に未翻訳と気づけること。
   色だけに依存せず明示的な文言も残す。両候補に共通の達成条件を適用する。
2. **実現・維持の負担**：標準で得られる範囲、追加する設定やコード、テーマ更新時の確認を比較する。
   同じ見た目に仕上げる必要はない。

現状は「Starlightは標準の注釈表示に利点がある」「VitePressのPoC実装は視認性の改善が必要」と評価する。
VitePressで実現できないことを示す結果ではなく、この差だけでSSGを決定しない。
注釈の存在を確認する自動テストだけでは、気づきやすさの合格判定はできない。
次の改善ではVitePressの注釈を本文から区別し、実装量を記録したうえで同じ条件で再確認する。
2026-11-17にVitePressの注釈を改善した。タイトル・本文より前に、標準テーマの`custom-block warning`を使った背景色付きの案内枠を配置し、太字の「未翻訳のドキュメント」と英語原文を表示する説明を追加した。`role="note"`と日本語の言語指定も付与した。独自CSS・テーマ・依存関係の追加はなく、既存レンダラーのHTMLのみを変更した。テーマ更新時にはこの標準クラスによる表示を再確認する。改善前の指摘は上記の履歴として保持する。

## 比較表

| 観点                       | VitePress                                                       | Starlight                              |
| -------------------------- | --------------------------------------------------------------- | -------------------------------------- |
| 同じページでの言語切り替え | 標準の言語ナビゲーション                                        | 標準の言語セレクター                   |
| 未翻訳の日本語URL          | 生成処理で英語ページを作成                                      | 英語エントリーから標準機能で生成       |

Starlightではフォールバック関連の独自コードを減らせる。一方、翻訳管理、ハッシュ比較、
安全性の検証、バージョン統合はどちらでも必要となる。VitePressの現在の追加処理は
カスタムテーマや入力MarkdownのHTML許可を必要としていない。

それぞれCtrl+Cで停止する。既存の英語URLも利用できる。

- `http://127.0.0.1:4173/docs/vitepress/next/ja/profiling/`
- `http://127.0.0.1:4174/docs/starlight/next/ja/profiling/`

nextのProfiling Guideは本リポジトリ所有の翻訳例で、人による翻訳校閲前と明記している。

英語6ページはgitlode本体を正本とする。

## 制約と残作業

- オーナーのプレビュー確認は済んでいるが、キーボード・モバイル・アクセシビリティの網羅的な
  検証完了を意味しない。注釈の視認性は改善後にオーナー確認済み。
- 言語切り替えでは見出しのフラグメントIDを翻訳しないため、日本語の見出しに切り替えた際に
  元の節の位置を引き継げない場合がある。ページ単位の切り替え先は検証済み。
- 英語フォールバックの本文リンクは英語へ、日本語サイドバーは日本語へ移動する。
- ハッシュ一致は翻訳品質や承認を意味しない。更新警告はユニットテストで検証しているが、
  通常の固定サンプルはハッシュが一致した状態である。
- Starlightの任意のi18nコレクション・独自404に関する警告は残る。フォールバックと標準404は
  ビルドできている。検索は無効のまま。
- stable／next統合、stable翻訳スナップショット方針、デプロイ、ホスト上のCI、依存関係の指摘への対応、
  最終的なSSG選定は未完了。

## 文書間リンクの調査（2026-11-17）

オーナーが未翻訳注釈を再確認し、VitePressも同等の条件を満たすと判断した。
注釈の視認性については、この再確認をもって今回の改善を受け入れ済みとする。

別途、Profiling Guideの文書参照がGitHubへ遷移することを確認した。
生成済みの`run-cncumF`で、両SSG・英語／日本語の4ページすべてに同じリンク先が存在する。

| 元の相対リンク                                 | 出現数（各ページ） | 現状の変換先                      |
| ---------------------------------------------- | -----------------: | --------------------------------- |
| `design/telemetry.md#worker-telemetry-session` |                  1 | 固定nextコミットのGitHub blob URL |
| `design/cli.md`                                |                  2 | 固定nextコミットのGitHub blob URL |

両文書は`config/publication.json`の6文書に含まれない。
`src/publishing/markdown.ts`の`rewriteLink`は、公開済みルートがある場合のみ内部URLを生成し、
それ以外の既存ファイルは固定コミットのGitHub URLへ変換する。
日本語の原稿は相対リンクを保持しており、翻訳や注釈スタイルによって外部URLになったものではない。

これは現在のPoCの公開範囲とリンク方針による挙動だが、「文書間参照はドキュメントシステム内で
完結する」というオーナーの期待を満たしていない。既存検証はこの外部リンクを許容しており、
その期待を受け入れ条件として検証していなかった。

対応には、参照先を明示的な公開対象に追加し、本文・参照先・フラグメントを検証する必要がある。
未翻訳なら日本語URLで英語フォールバックを表示する。公開対象とサイドバー掲載は独立しているため、
公開するだけで必ずサイドバーへ追加する必要はない。さらに、製品文書の意図しない外部化を検知する
検証と、コード・公開対象外資料など意図的なGitHubリンクの区別が必要となる。
リンクをたどって全ファイルを自動公開する方針には変更しない。
今回は原因調査と記録までで、公開範囲・変換処理は変更していない。

### 調査後の決定

2026-11-17、オーナーはPoC対象外の文書への外部リンクをPoCの制限として許容し、修正不要と判断した。上記の対応案はPoC中には実施せず、実運用までの対応事項として保持する。本番移行レビューでは、必要な文書間参照がサイト内で解決できることを確認する。

### 比較の完了

オーナー判断により、未翻訳文書への対応比較は完了。PoC対象外文書への外部リンクを許容する制限と、実運用での対応事項は維持する。次の比較工程は[stable／next統合](versions.md)。
