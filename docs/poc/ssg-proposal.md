# 0001 — 静的サイトジェネレーターの選定提案

状態：2026-11-17、将来性の追加調査を反映。**現行版比較ではStarlightを小差で推奨。VitePress v2も有力な選択肢であり、総合選定は未確定。**
判断者：プロジェクトオーナー。次の対応：推奨とトレードオフのレビュー。
選定後は確定した理由と条件を英語の意思決定記録へ移す。

## 提案

以下の比較はVitePress 1.6.4とStarlight 0.43.1に対するもの。
追加の[将来性・v2移行調査](future-outlook.md)では、alpha.21への小規模な変更でビルド・検索検証が成功し、依存監査も0件になった。
v1の監査指摘や検索制約をVitePress全体の欠点として固定しない。
v2も有力な採用候補として検討する。ただしv2のブラウザ・Ubuntu CI確認は未実施であり、現行版と同じ受け入れ実績とは扱わない。
Starlightもbetaでminor更新時の破壊的変更があるため、alphaとの名称差だけで安定性を順位付けしない。

今回の用途では **Astro Starlightを採用することを提案する**。差は小さく、VitePressも要件を満たす。
主な理由は、英語を正本とし日本語訳が段階的に揃う運用に対して、未翻訳ページの生成・注釈・本文言語の扱いを標準機能に任せられること。
注釈の見た目の好みではなく、将来こちらで維持する処理を減らせる点を評価した。

共通の取得・選択・翻訳管理・複数バージョン構築はどちらでも必要であり、システム全体が大幅に簡単になるわけではない。
Vueの経験を重視するならVitePressを選ぶ合理性もある。チームのAstro/Vueの習熟度は今回測定していない。

## 判断に用いた重み

| 観点                   | 判断                                                                          |
| ---------------------- | ----------------------------------------------------------------------------- |
| 主要機能               | 両者が必要十分。オーナーのブラウザ評価を採用                                  |
| 未翻訳対応の保守       | Starlightを支持。標準機能で成立し、独自レンダラーが不要                       |
| 設定・型検査           | VitePressを支持する要素。現行の設定・Vueテンプレートまで型検査済み            |
| 依存更新               | 固定したVitePress系統に監査指摘が残る。Starlight側もAstroとの互換性維持が必要 |
| 検索                   | VitePressのほうが高機能というオーナー評価。ただし選定の決め手にしない         |
| 外観・単発のビルド時間 | 決め手にしない                                                                |
| CI・再現性             | 両者成功。差なし                                                              |

実装箇所、設定量、更新時の確認事項と反証は[保守性の比較](maintenance.md)にまとめた。
[総合評価](evaluation.md)、[検索](search.md)、[再現性・CI](reproducibility.md)も根拠とする。

## VitePressを選ぶ場合の見通し

未翻訳表示は既に実装・検証済みであり、実現困難ではない。Vue/TypeScriptの開発体験を優先する場合は有力。
追加の責務はfallback用ページと注釈・本文言語の維持、および現行依存監査への対処である。
バージョン切替のVue部品は標準navへ簡略化できる可能性があるため、現行のファイル数だけを理由に不利としない。

## 選定後の作業と保留事項

1. オーナーが採用候補を決定し、理由を意思決定記録へ移す。
2. 採用側を残して比較専用の依存・分岐を整理し、型検査と回帰検証を維持する。StarlightならAstro専用型検査の追加を検討する。
3. 公開対象文書・画像、内部リンク、stable翻訳の運用方針を確定する。
4. 標準URL`https://gitlode.github.io/docs/`用の公開ワークフローを準備し、公開の承認と実サイト確認を行う。

候補は承認まで両方保持する。この提案はPoC終了や本番公開の承認ではない。
Pages配信は未実施であり、CIでの成功を公開成功と扱わない。
