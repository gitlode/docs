# 0001 — 静的サイトジェネレーターの選定提案

状態：2026-11-18、オーナーが **VitePress v2の採用を決定**。本提案のレビューは完了。
決定理由：両候補に決定的な機能差はなく、未翻訳対応の独自コードは保守可能な規模と判断し、Vue.jsを使う開発基盤への好みを優先した。
確定した決定は[ADR 0001](../decisions/0001-use-vitepress-v2.md)に記録。以下のStarlight推奨は判断過程の記録として保持し、現在の採用方針とは区別する。
次の対応：v2へ実装を一本化する。公開・PoC終了の判断は別途行う。

## 結論

VitePress 2.0.0-alpha.21とStarlight 0.43.1（Astro 7.4.12）は、今回確認した必要機能をともに満たす。
そのうえで、英語を正本とし日本語を段階的に翻訳する今回の運用には、**標準の未翻訳対応を持つStarlightを小差で推奨する**。

v2をalphaという理由で不利には扱わない。v2のブラウザ確認・Ubuntu CIは完了し、オーナーも確認範囲内で未完成な部分は見られないと評価した。
v1よりv2を優先するオーナー判断を採用し、v1は積極的な採用候補から比較基準へ移す。実装は最終選定まで保持する。
この判断はv2がStarlightより優位と決まったことを意味しない。

今回の推奨理由は、安定版という名称、外観、v1の依存監査指摘ではない。
未翻訳表示という継続的な要件を、どこまでこちらの独自処理として維持するかである。

## 選定に残る違い

| 観点                       | VitePress v2                                                         | Starlight                                    | 判断への重み                             |
| -------------------------- | -------------------------------------------------------------------- | -------------------------------------------- | ---------------------------------------- |
| 基本機能・言語・簡易版切替 | 実装・自動検証・オーナー確認済み                                     | 同左                                         | 必須条件。両者合格                       |
| 未翻訳対応                 | 英語本文の日本語ページを生成し、独自レンダラーで注釈・本文言語を付与 | 標準fallbackに任せる                         | Starlightを小差で支持                    |
| 開発時の型検査             | 設定とVueテンプレートまで検査済み                                    | Astro専用型検査の追加余地                    | 現行実装ではv2を支持。ただし改善可能な差 |
| 設定・フレームワーク知識   | Vue、Markdownレンダラー、テーマslot                                  | Astro、content loader、processor、部品上書き | Starlightの設定全体が単純とは言わない    |
| 検索                       | v1より日本語検索が改善。確認した用途で十分                           | 必要十分と評価済み                           | 低い。決め手にしない                     |
| 更新互換性                 | alpha間・正式版までの変更を検証する                                  | minor更新の破壊的変更を検証する              | 両者必要。名称だけで順位付けしない       |
| 機能開発の将来             | v2が開発の中心という見立て                                           | 継続的な更新と改善を確認済み                 | 将来性は参考。長期的優劣は断定できない   |
| CI・代表ブラウザ操作       | 成功                                                                 | 成功                                         | 差なし。Pages実配信は両者未確認          |

Starlightの標準fallbackは[公式i18n資料](https://starlight.astro.build/guides/i18n/)にも記載され、PoCで動作確認済み。
v2を公式の導入経路として扱うことは[quickstart](https://vitepress.dev/guide/getting-started)で再確認した。
この二つの事実と、将来の品質・互換性保証は区別する。

## 推奨の強さと反対の選択をする理由

Starlightの利点は限定的である。取得・公開範囲・翻訳鮮度・版構築・出力検証は共通処理であり、選定だけで消えない。
標準fallbackも翻訳レビューや変更検知は代行しない。独自の版切替部品も残る。
採用時にはAstro側の型検査を整備し、CSSと上書き部品の更新確認を行う必要がある。

VitePress v2の独自fallbackは既に実装・検証済みで、現時点で問題のある機能ではない。
Vue/TypeScriptでの保守や将来のカスタマイズを重視し、この小さな独自処理を維持すると判断するなら、**v2の採用も十分合理的**である。
ただしチームのVue/Astro習熟度は測定しておらず、Vueが得意だとは仮定していない。

今回の検証から、どちらを選んでも大きな機能上の妥協はない。
標準の未翻訳対応を優先するならStarlight、Vueでの開発を優先するならv2、という判断が残る。
後者を優先するというオーナー判断があれば、本提案の小差の推奨を変更できる。

## 以前の評価から取り除く根拠

- v1の監査3項目をv2の欠点として扱わない。2026-11-17のv2置換実験では依存整理後0項目だった。現在も0件という保証ではなく、採用候補に整理後は再監査する。
- v1の日本語検索制約をv2へ流用しない。v2で改善を確認済み。
- v2のブラウザ・CIが未確認という留保は解消した。網羅的な端末確認や実Pages公開は別途必要。
- 2版同居のnpm alias、SSR noExternal、複製設定は比較環境の都合であり、v2単独採用の恒久的コストと数えない。
- ファイル数・行数、単発のビルド時間、alpha/betaの名称差を選定の決め手にしない。

## 選定後の具体的な順序

1. オーナーのSSG決定を記録し、採用理由を英語のADRへ移す。
2. 不採用候補と比較専用処理を整理する。採用版の厳密固定を保ち、型・回帰・検索・CI検証を継続する。
3. 本番の公開文書・内部リンク・画像などの範囲、stable翻訳の運用方針、日本語例文のレビューを確定する。
4. 標準URL https://gitlode.github.io/docs/ 用の完全な成果物と公開ワークフローを用意し、公開承認と実サイト確認を行う。

SSG決定とPoC終了・本番公開は別の判断。今回の資料更新では候補の削除やデプロイを行わない。
